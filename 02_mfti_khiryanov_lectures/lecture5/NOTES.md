# Лекция 5. Структурное программирование и декомпозиция

Курс: «Практика программирования на Python 3», МФТИ, 2020, Т. Хирьянов.
Конспект — авторский пересказ; `house.py` — собственная иллюстрация подхода.

## Главное
1. **Декомпозиция** — делим задачу на подзадачи: функции, классы, модули.
   Границы проводим по логической связности данных, а не «где удобно».
2. **Сверху вниз (top-down)**: сначала интерфейс (`draw_house(...)`),
   потом реализация подпрограмм. **Снизу вверх (bottom-up)** — рефакторинг
   и сборка уже написанного кода.
3. **Консистентное состояние**: программа в любой момент запускается и не падает.
   На этапе проектирования функции-заглушки (`pass` или `print()`).
4. **«Призраки»** — знания, которые есть только в голове автора
   (где опорная точка: угол или центр?). Убираем их через docstring
   до написания тела функции: параметры, единицы, координаты, возврат.
5. **Git-культура**: коммит — законченный логический шаг, без «сломанных» коммитов;
   `git diff` перед коммитом для самопроверки, `git commit --amend` для правок.
6. **Pygame**: размеры частей дома считаем от общих `width` и `height`,
   параметры сначала «прозваниваем» через `print()`.

## Чек-лист перед коммитом
- [ ] Программа запускается
- [ ] Просмотрен `git diff`
- [ ] У новых функций есть docstring с контрактом
- [ ] Коммит делает одну логическую вещь
